# CantoDuplex 种子真集采集协议 v0.1(草案,待试录 2 对后修订)

> 目标:20h 双通道粤英对话(先 10–20h 验证 pipeline),其中 10h 精标事件标签。
> 三大用途:控制监督金标签 / 合成数据 timing 分布源 / 评测真声学轨(留出部分永不参训)。

## 1. 三个子集与配比

| 子集 | 占比 | 内容 | 目的 |
|---|---|---|---|
| S1 自由闲聊 | 40% | 熟人远程通话,无脚本,粤语为主自然混英 | 自然应声/抢话/overlap 的 timing 分布 |
| S2 任务角色扮演 | 35% | 客服脚本(查账单/改预约/投诉/办套餐),一方扮客服 | 目标域(客服)的事件分布 + 埋事件指令 |
| S3 Wizard-of-Oz | 25% | 一方扮 agent(照稿念、按规则响应),一方当用户 | 人对机的打断时机分布(≠人对人,最终服务场景) |

## 2. 录音规范(核心:双通道 = 各自本地录音)

- **协议**:两人远程通话(电话/网络均可),**各自用本地设备录自己的麦**(手机录音 app 或电脑 Audacity),不录对方声音 → 天然通道分离,无串音;
- 格式:48kHz / 16bit / 单声道 WAV(交付后统一下采样出 16k 与 8k 电话版);
- **关闭系统降噪/回声消除**(保留自然呼吸、口腔音——合成数据没有的真实指纹);
- **对齐信号**:通话开始与结束时,双方各拍手三下(或播放约定 beep);会后用互相相关对齐,要求对齐误差 < 20ms;录音超过 30min 的 session 中途加一次对齐信号(防时钟漂移);
- 每 session 30–45min,同一对参与者最多贡献 3 session(防说话人过拟合);
- **环境多样性配额**:至少 1/3 session 在自然嘈杂环境(家中开电视 / 街上 / 茶餐厅),禁止全部安静房间;各录各麦的协议下环境噪声天然进入对应通道——噪声真实、标签仍干净;meta.json 记录环境类型;
- **设备多样性**:手机内置麦 / 有线耳机 / 蓝牙耳机混配,禁止统一发放同型号设备。

## 3. 事件指令卡(S2 用,关键设计)

给"用户"方发放指令卡,**不告知"客服"方具体时机**:
- 【纠正】在对方讲解过程中,至少一次用"唔係/no no/wait"开头纠正一个信息(如日期、金额);
- 【混语纠正】至少一次纠正必须句内切换("唔係啊 I mean 下个月");
- 【应声】对方长段讲解时自然应声(係/嗯嗯/okok),不要刻意;
- 【旁侧】至少一次假装对屋内他人说一句话(如"帮我攞杯水"),音量自然;
- 【抢话】至少一次在对方未讲完时直接开始自己的问题。

## 4. WoZ 协议(S3)

- agent 扮演者:照准备好的客服话术念(语速平稳,模拟 TTS 节奏);被打断时按简单规则响应:听到明显插话→停下问"你想讲咩?";听到应声→继续念;
- 扮演者规则刻意做得**像目前市面 agent 一样笨**(应声也停),诱发用户的真实不耐烦与修复行为——这些修复模式是训练 RESUME 的素材;
- 用户方拿真实任务目标(不给台词)。

## 5. 同意与合规

- 录音前双方签署:双通道录音同意、用途(训练交互控制模型,**不做声音克隆**)、可撤回机制(凭 session id 删除)、发布分级(仅内部训练 / 可入公开 benchmark 留出集,单独勾选);
- 元数据记录:语言背景(粤/英熟练度)、关系(朋友/同事/陌生)、设备型号、环境(安静室内/街上/办公室);
- 参与者报酬按 session 结算,精标质检不合格的 session 照付但不入库。

## 6. 文件与元数据 schema

```
data/seed/<session_id>/
  spkA.wav  spkB.wav          # 各自本地原始录音
  aligned/spkA.wav spkB.wav   # 对齐后
  meta.json                   # 见下
  labels.eaf                  # ELAN 标注(精标子集)
  labels.json                 # 从 eaf 导出的事件 JSON(harness schema)
```

meta.json 必填:session_id、子集类型(S1/S2/S3)、日期、参与者匿名 id、语言背景、设备、环境、对齐误差 ms、同意书版本、发布分级。

## 7. 标注(精标 10h)

事件标签表(与 harness/schema.py 的 EVENT_CLASSES 一一对应):
`backchannel`(应声)/ `correction`(纠正,含混语)/ `floor_claim`(抢话)/ `cooperative_completion`(协作接话)/ `side_speech`(旁侧对话)/ `background_noise`(环境人声/电视)/ `filler`(填充词、咳嗽)/ `echo`(对方声音串回)。
每个事件加属性:language(yue/en/mixed)、切换点时间(如有)、addressed_to(对方/他人)。
- 工具:ELAN,模板随协议发放;时间精度 10ms;
- 质检:10% 双人标注,事件级 IAA(Cohen's κ)≥ 0.7 才放行;分歧样本保留双标签(分歧本身有科学意义,不强行合并);
- 标注顺序:先标 S2(事件密度最高、指令卡可辅助定位),再 S3,S1 最后。

## 8. 质检清单(每 session 入库前)

- [ ] 对齐误差 < 20ms(拍手互相关)
- [ ] 无削波(峰值 < -1dBFS 占比 > 99.9%)
- [ ] 无串音(A 通道内 B 的能量 < -40dB)
- [ ] 时钟漂移 < 50ms/30min(首尾对齐信号差)
- [ ] meta.json 完整、同意书归档
- [ ] 粤英混说比例抽检(S1/S2 至少 10% 语句含句内切换,否则调整招募/指令)

## 9. 试录计划

先跑 2 对 × 各 3 session(每子集 1 个)≈ 3h,走完"录→对齐→标→质检→入 harness"全流程,按暴露的问题修订本协议至 v1.0,再放量招募。
